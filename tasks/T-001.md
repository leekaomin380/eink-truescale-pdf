## 1. 背景（Why）
本项目已有一个可用的图形界面：`gui/server.py`（仅用 Python 标准库起的
本地 HTTP 服务，监听 127.0.0.1）+ `gui/index.html`（单页前端）。它把电子书
按电子墨水屏原生物理尺寸转成 PDF。所有转换逻辑都在 `book.sh` 里，服务只是
一层壳，前端通过 HTTP API 调用它。

当前启动方式是 `./gui.sh`：起服务 + 用默认浏览器打开 http://127.0.0.1:8777。
问题：图形界面用户想避开终端，而现在每次用都要敲命令、且开在浏览器标签里，
服务一关就不可用。

目标是做一个**双击即开、自带原生窗口、不碰终端、不占浏览器标签**的 .app，
但**不重写任何转换逻辑**——继续复用现有的 Python 服务，.app 只是把它
包起来并用原生窗口显示。

## 2. 目标（What）
一句话：产出一个 macOS `.app`，双击后在原生窗口里显示现有 GUI，退出时
干净地关掉后台服务。

子目标（每条完成后应可验证）：
- 完成后，从**访达双击** .app，应弹出一个原生窗口显示现有界面（不是浏览器、
  不是终端）。
- 完成后，在该窗口里拖入 EPUB → 转换 → 预览 → 另存/发送，全部功能与
  `./gui.sh` 一致。
- 完成后，退出 .app（Cmd+Q 或关窗口），`ps aux | grep server.py` 应查不到
  遗留的 python 进程。
- 完成后，现有的 `./gui.sh` 与 `./test.sh` 行为不变，仍能独立运行。

### ⚠️ 已知坑（务必先读，这些是本项目已经栽过的同类问题）
1. **PATH 坑（最致命）**：Finder/launchd 启动的 GUI 应用拿到的是最小 PATH
   （通常只有 /usr/bin:/bin），**不含 /opt/homebrew/bin**。后果是双击后：
   ① 可能连 python3 都找不到；② 即使找到，子进程 server.py 再调
   pandoc/typst/pdftoppm 时也会找不到。本项目在 macOS 快捷指令上已经因为
   这个坑栽过两次。**必须在启动 python 子进程时显式注入包含
   /opt/homebrew/bin 的 PATH**（同时建议注入 LANG/LC_ALL=en_US.UTF-8，
   原因见下一条）。
2. **locale 坑**：最小环境下 LANG 为空会导致 pandoc 把 UTF-8 中文当 latin1
   → 乱码。给子进程注入 LANG=en_US.UTF-8、LC_ALL=en_US.UTF-8。
3. **WKWebView 的 ATS 坑**：WKWebView 默认禁止加载 http（非 https）。加载
   http://127.0.0.1 会**静默失败、白屏**。必须在 Info.plist 里为 localhost
   开 App Transport Security 例外（NSAllowsLocalNetworking 或针对
   127.0.0.1 的 NSExceptionDomains）。
4. **就绪时机坑**：现有 gui.sh 用 `sleep 1` 等服务起来，很脆。原生 app
   应当**轮询端口直到真正 listening 再加载 URL**，否则偶发白屏。
5. **端口占用坑**：不要写死 8777——本机可能已有一个 gui.sh 起的服务或
   遗留进程占着它。应选一个空闲端口再传给 server.py。
6. **孤儿进程坑**：app 崩溃或强退时，python 子进程可能残留。需在退出路径
   （applicationWillTerminate、窗口关闭）里终止子进程；建议记录 PID 并
   在下次启动时清理同名遗留进程。

## 4. 具体步骤
1. **技术选型（已定，按此执行，不要另选）**：用 **Swift + WKWebView** 写一个
   极薄的原生外壳，放在 `gui/mac/`。
   - 为什么不用 py2app/PyInstaller/pywebview：本项目刻意零第三方 Python 依赖
     （只用标准库），引入打包器或 pywebview 会破坏这一点；而 swiftc 本机已有，
     WKWebView 能给真正的原生窗口，且能让 server.py 保持为唯一逻辑来源。
   - 为什么不用「浏览器 app 模式」（Chrome --app=）：依赖特定浏览器、脆弱，
     不算真正的原生窗口。
2. **外壳职责**（Swift）：
   a. 启动时选一个空闲端口（例如 bind 到 0 拿到系统分配的端口后释放，或从
      一个基准端口向上探测），记下来。
   b. 用 `Process` 启动 `python3 <仓库>/gui/server.py <port>`，并为该子进程
      设置 environment：PATH 前置 /opt/homebrew/bin:/usr/local/bin，
      LANG/LC_ALL=en_US.UTF-8。python3 用绝对路径
      /opt/homebrew/bin/python3（不要依赖继承的 PATH 找它）。
   c. 轮询 127.0.0.1:<port> 直到可连接（带超时，比如 10 秒，超时则在窗口里
      显示可读的错误，而不是白屏）。
   d. 在 WKWebView 里加载 http://127.0.0.1:<port>。
   e. 窗口标题设为「电子书转换 · Quaderno」，给一个合理的默认窗口尺寸
      （宽约 1100、高约 720，可调）。
   f. 退出/关窗口时 terminate() 子进程。
3. **仓库路径解析**：外壳需要知道仓库在哪。本任务是本机自用，采取「引用
   现有仓库」而非「把 python+仓库打包进 app」的方式。仓库路径用一个
   常量，默认 /Users/km/projects/print-to-quaderno；若该常量对应目录不存在，
   在窗口里报清楚的错，不要静默。
   （完全自包含、可拷到别的机器的打包方式是更大的工程，见第 7 节，本任务不做。）
4. **打包脚本**：写 `gui/build-app.sh`，用 swiftc 编译外壳并组装出标准
   .app bundle 结构（Contents/MacOS/ 可执行文件、Contents/Info.plist、
   Contents/Resources/）。Info.plist 要包含：CFBundleName、
   CFBundleIdentifier、LSMinimumSystemVersion、上面第 3 条的 ATS 例外、
   NSHighResolutionCapable=true。脚本产出的 .app 放在 `gui/` 下或
   `dist/` 下（择一，写清楚）。
5. **README 增补**：在 README.md 里加一小节「打包成 App」，写明如何用
   build-app.sh 生成、以及双击使用方式。不要改 README 其它部分。
