## 1. 背景（Why）
T-001 已把本地 Web GUI 包装成原生 macOS .app 并安装到
/Applications/Quaderno Converter.app。真机使用后发现三点要改：

1. **「拖入电子书」框点击无效**（拖拽可用）。根因：WKWebView 默认不处理
   `<input type=file>` 的文件选择，需要原生外壳实现 open-panel 代理。
   这是打包成 app 后才暴露的坑，浏览器版没有。
2. **中文字体下拉显示英文名**（PingFang SC 等），希望改为中文名（苹方等）。
3. **调参要整本重转才能预览**。希望：调好参数先看**快速预览**，满意了再
   生成完整 PDF。即把「预览渲染」和「成品渲染」分成两档。

## 2. 目标（What）
三个独立可验证的改进：
- A. 完成后，在 app 窗口里**点击**「拖入电子书」框，能弹出系统文件选择框
  并成功选中 EPUB（与拖拽等效）。
- B. 完成后，中文字体下拉显示中文名（如「苹方」「宋体」「黑体」），但实际
  传给 book.sh 的仍是 typst 认的真名（PingFang SC 等），转换结果不变。
- C. 完成后，存在两档渲染：**预览档**只渲染样章（约前一章 / 前若干页），
  亚秒级，用于调参时即时查看；**成品档**渲染整本，仅在保存 / 发送整本时触发。
  另提供「发送样章到设备」用于在真墨水屏上预览。

## 3. 输入与现状

- `gui/index.html` —— 前端单页。字体下拉在 `fill($('#cjk'), r.fonts.cjk…)`；

- `book.sh` —— 转换核心。已有 `--size/--font/--margin/--leading/--lang/

  `$MD_FORMAT`（关掉 citations/tex_math_dollars）与 `book-filter.lua`。**

### 关键事实（影响你的工作方式，务必知悉）

### ⚠️ 已知坑（务必先读）
1. **A 的根因**：WKWebView 不像浏览器会自动弹文件框。必须让 WKWebView 的
   `uiDelegate` 实现
   `webView(_:runOpenPanelWith:initiatedByFrame:completionHandler:)`，
   在其中弹 `NSOpenPanel`（限定 .epub/.fb2/.html/.md），把选中的 URL 通过
   completionHandler 交回。不实现它，点击就是静默无反应。
2. **B 的陷阱（会静默毁排版）**：中文名只能是**显示层**。下拉 `<option>` 的
   value 必须仍是真名（PingFang SC）。若把 value 也改成「苹方」，book.sh
   的 `--font 苹方` 会让 typst 找不到字体而**静默 fallback**，用户看不出、
   但排版已被悄悄换字体。映射表里没有的字体，直接显示其真名，不要瞎译。
3. **C 的陷阱**：样章渲染必须走**和成品完全相同的渲染路径**——同样的页面
   几何（157/A5，1:1，≈445pt 页宽）、同样的 `$MD_FORMAT`、同样的
   `book-filter.lua`。否则：① 预览尺寸不对，失去 1:1 的意义；② 会重新踩
   @词/$变量崩溃、内部锚点崩溃这些已修的坑。
4. **C 的"快"从哪来**：不要"先整本渲染再截前几页"——那没有变快。加速必须
   来自**只渲染更少的内容**（截断到第一章）。典型书约 2 秒整本，样章目标
   应明显更快（亚秒级）。
5. **别破坏成品档**：给 book.sh 新增样章能力时，不传新标志时的默认行为
   （整本）必须与现在**逐字节一致**，否则 test.sh 会红、且影响 deliver 链。

## 4. 具体步骤

### Part A — 修复点击选文件（改 AppShell.swift）
1. 让 AppDelegate（或单独一个类）成为 `WKUIDelegate`，赋给 `webView.uiDelegate`。
2. 实现 open-panel 方法：弹 NSOpenPanel，`allowedContentTypes` 或
   `allowedFileTypes` 限定 epub/fb2/html/md，单选，把结果 URL 数组交回
   completionHandler。
3. 重编译 + 重装（见步骤 6）。

### Part B — 中文字体名（改 index.html，必要时 server.py）
1. 在 index.html 建一个「真名 → 中文名」映射，至少覆盖：
   PingFang SC→苹方、Songti SC→宋体、Heiti SC→黑体、STSong→宋体（华文）、
   Hiragino Sans GB→冬青黑体、Noto Serif CJK SC→思源宋体、
   Source Han Sans SC→思源黑体、Source Han Serif SC→思源宋体。
   （若你判断某些映射不准，用最通行的叫法；拿不准就保留真名。）
2. 中文字体下拉：`<option value="真名">中文名</option>`。西文字体下拉不变
   （Charter/Helvetica Neue 等保持英文）。
3. 确认 cfg() 组装 `fonts` 时取的是 option 的 value（真名），不是显示文本。

### Part C — 两档预览
1. **book.sh 增加样章档**：新增一个标志（如 `--sample`），只渲染正文的
   第一章（内容截断到**第二个顶级标题 `# ` 之前**），其余参数/模板/
   方言/lua 过滤器全部照旧。不传该标志时行为与现在完全一致。
   - 推荐实现：先 `pandoc "$INPUT" -t markdown`（或用已判定的 FROM 读入）
     得到中间 markdown，用 awk/sed 截到第二个 `^# ` 之前，再走原有渲染
     （务必仍经 `$MD_FORMAT` 与 `book-filter.lua`）。具体机制你定，
     但必须满足坑 3、坑 4。
   - 样章不需要完整目录页/大纲也可接受（预览是看排版，不是看导航）；
     若容易保留就保留，不强求。
2. **server.py**：`/api/preview` 或新增 `/api/render` 支持"样章"参数，
   调 book.sh 的样章档产出一个小 PDF，再交给现有 pdftoppm 逐页显示。
   成品渲染（保存/发送整本）继续走整本档。
3. **index.html 按钮语义**（可按你判断微调命名，但行为需如下）：
   - 「预览」：样章档渲染 → 右侧显示，可翻页。这是调参主循环，要快。
   - 「发送样章到设备」：样章档渲染 → 走 /api/deliver 投递（若检测到
     QUADERNO 客户端才显示，与现有 send 按钮同规则）。
   - 「生成 PDF」/「另存」：成品档（整本）→ 保存。
   - 「发送整本到设备」：成品档 → 投递（沿用现有 send 逻辑）。
   - 改参数后，明确提示预览已过期、需重新点「预览」（现有已有类似提示，
     沿用即可）。
