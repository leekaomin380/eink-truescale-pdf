## 2. 背景（Why）

这个 macOS app 目前**无法分发给任何其他人**。根因在这一行：

```swift
// gui/mac/ConversionViewModel.swift:90
let scriptDir = URL(fileURLWithPath: #file)
    .deletingLastPathComponent().deletingLastPathComponent().deletingLastPathComponent()
repoURL = scriptDir
```

`#file` 是 **Swift 编译期常量**，记录的是编译这台机器上的源文件绝对路径。
已实证：编译产物二进制里烧着 `/Users/km/projects/print-to-quaderno/gui/mac/ConversionViewModel.swift`。

后果：
- 自己 clone + 自己编译 → 能用（`#file` 是自己的路径）
- **把编译好的 .app 发给别人 / 放进 GitHub Release → 一启动就失败**
- 用户 clone 后移动了仓库目录 → 已编译的 app 失效

因此项目当前只能分发源码，每个用户必须自备 Xcode 编译。本任务要消除这个限制。

## 3. 现状：运行时依赖闭包（已由委托方查清，可直接采用）

`repoURL` 只用于定位这几个文件（`ConversionViewModel.swift` 第 121/156/257/411 行）：

| 文件 | 用途 | 大小 |
|---|---|---|
| `config.sh` | app 读取默认排版参数 | 2.1 KB |
| `devices.json` | 设备尺寸库 | 4.0 KB |
| `book.sh` | 实际渲染，app 以子进程调用 | 7.8 KB |

而 `book.sh` 自身在运行时还会拉取同目录的（第 25/26/130 行）：

| 文件 | 用途 | 大小 |
|---|---|---|
| `config.sh` | `source` 进来 | （同上） |
| `deliver.typ` | typst 模板 | 3.4 KB |
| `book-filter.lua` | pandoc 过滤器 | 1.2 KB |

**完整闭包 = 5 个文件，共约 18 KB。** 全部打进 bundle 完全可行。

### 一个已澄清的设计疑虑（不必再纠结）

`config.sh` 对 CLI 用户是"可编辑的配置文件"，但**app 只把它当默认值来源读一次**——
GUI 上的字体/字号/边距/行距全部通过命令行参数（`--size`/`--font`/`--margin`/
`--leading`/`--page`）在运行时覆盖，**app 从不写回 `config.sh`**（已核实）。
因此把它作为**只读资源**打进 bundle，不损失任何 GUI 功能。

## 4. 目标（What）

- 编译产物 `.app` **不再包含任何编译机的绝对路径**，拷到另一台 Mac（或改名/移动仓库目录后）仍能正常工作。
- CLI 入口（`deliver.sh` / `book.sh` / `gui.sh`）行为完全不变，仍从仓库根目录工作。
- 现有 GUI 功能全部不变：三种输入模式、预览、另存 PDF、发送到设备。
