# 任务 T-004：GUI 新增「粘贴文本」模式 —— Markdown 文本 → 1:1 PDF

## 1. 背景（Why）
当前 GUI 只有一个入口：选电子书文件（EPUB）→ 渲染 → 预览 → 保存/发送。
产品负责人要加第二个入口：**直接粘贴一段 Markdown 文本**（如从对话、网页复制来的
内容）→ 用同一套 1:1 墨水屏排版渲染 → 预览 → 另存 PDF / 发送到 Quaderno。

这相当于把项目里 `deliver.sh`（剪贴板文本→PDF）的能力搬进 GUI，配上电子书模式
已有的字体/字号/边距/行距控件与预览、复用逻辑。

## 2. 目标（What）
- GUI 顶部提供**模式切换**：「电子书转换」/「粘贴文本」。
- 粘贴文本模式：一个 Markdown 文本框 + 与电子书模式**共用**的排版控件
  （中文字体/西文字体/字号/边距/行距/语言/目标设备）。
- 「预览」「另存 PDF」「发送到 Quaderno」在该模式下同样可用，行为与电子书模式一致
  （整本渲染并缓存；参数/文本未变则复用产物，变则重渲）。

## 3. 输入与现状

### 涉及文件（本任务允许修改）
- `gui/index.html` —— 单视图。当前有：文件拖拽/点击区、控件、`预览/发送/另存`
  按钮、右侧预览、底部技术行。已有 `DIRTY` 标记（参数变化置位）与
  `cfg()`（读控件值）、`show()`（翻页预览）、`update()`（实时读数）。
- `gui/server.py` —— 标准库服务。`/api/convert`（收 `{path, config}` → 调 book.sh）、
  `/api/preview`（pdftoppm 出图）、`/api/save`、`/api/deliver`、`/api/upload`。
- `book.sh` —— 渲染核心。md 输入时 `FROM=$MD_FORMAT`（已关 citations/
  tex_math_dollars，防 @词/$变量崩溃）。**当前对所有输入都加
  `--toc --toc-depth=3` 与 `-V chapterbreak=true`（电子书行为）。**

### 关键设计判断（已定，按此实现）
**粘贴文本必须走「plain」渲染：不加目录页、不加强制分章。**
理由：一段贴进来的文章/对话若被加上目录页、每个 `#` 标题另起一页，是荒唐的。
电子书需要目录与分章，短文不需要。因此：
- 给 `book.sh` 新增 `--plain` 标志：置位时**省略** `--toc --toc-depth=3` 与
  `-V chapterbreak=true`，其余（模板、页面几何、字体、`$MD_FORMAT`、
  book-filter.lua、locale/PATH）全部照旧。不传 `--plain` 时行为与现在逐字节一致。
- 粘贴文本模式渲染时，server 调 `book.sh --plain`。

### 关键事实
- 本任务**不改 Swift**，无需重编译 .app。安装版 app 实时读仓库的
  index.html/server.py/book.sh，重启 app 即生效。
- `book.sh` 现在等于上一个提交（HEAD）。本任务对它的改动应**只有** `--plain`
  这一新增分支。

### ⚠️ 已知坑
1. **@词/$变量**：粘贴的对话文本极可能含 `@某某`、`$PATH`、`$100`、邮箱、
   `@media`。必须确保渲染走 `$MD_FORMAT`（book.sh 对 .md 输入已是）。
   →server 把文本写成 **`.md` 后缀**的临时文件再交给 book.sh，才会命中
   `FROM=$MD_FORMAT`。写成别的后缀会走错分支。
2. **空文本**：文本框为空时不要渲染空 PDF，给出提示（类似电子书模式无文件时）。
3. **复用不变量**：粘贴模式下，`DIRTY` 除了参数变化，**文本框内容变化也要置位**，
   否则会拿旧 PDF 冒充新文本。保存/发送的 PDF 必须等于「当前文本 + 当前参数」所渲。
4. **不要破坏电子书模式**：两模式共用控件与预览，切换模式不应串味
   （比如切到粘贴模式后电子书的已载入文件、已渲 PDF 状态要合理处理，
   避免「粘贴模式却发送了上次的电子书 PDF」这种错乱）。
5. **别动 book.sh 默认路径**：`--plain` 只能是新增分支；不传时（电子书模式）
   必须仍加 TOC/分章。

## 4. 具体步骤
1. **book.sh**：新增 `--plain` 解析与变量（如 `PLAIN=1`）。在主 pandoc 调用处，
   用条件控制是否加入 `--toc --toc-depth=3` 与 `-V chapterbreak=true`：
   `--plain` 时不加，否则照旧。其余不动。
2. **server.py**：
   - `/api/convert` 接受可选的 `text` 与 `plain` 字段（与现有 `path` 二选一）。
     有 `text` 时：把文本写到 `WORK/paste_<唯一>.md`（**务必 .md 后缀**），
     以它为源，调 `book.sh ... --plain`。无 `text` 时走原 `path` 流程（电子书）。
   - `/api/preview`、`/api/save`、`/api/deliver` 操作的是产出的 PDF，无需区分模式，
     基本可原样复用。
3. **index.html**：
   - 顶部/侧栏加模式切换（两个标签或分段控件）：「电子书转换」「粘贴文本」。
   - 粘贴模式：把文件拖拽区替换/切换为一个 `<textarea>`（Markdown）。控件区不变。
   - 文本框 `input` 事件置 `DIRTY=true` 并提示「已改，请重新预览」。
   - 「预览」：粘贴模式下带 `text` + `plain:true` 调 `/api/convert`；成功后
     与电子书模式一样显示、翻页、清 DIRTY、启用保存/发送。
   - 「另存」「发送」：沿用现有 DIRTY 复用逻辑；粘贴模式重渲时同样带 `text+plain`。
   - 「另存」的默认文件名在粘贴模式没有源文件名 —— 可取文本首个 `# 标题` 或
     首行前若干字做默认名，取不到就用 `pasted.pdf`。
   - 模式切换时妥善重置状态（当前 PDF、DIRTY、按钮可用性），避免坑 4。
4. 不改页面几何、不改电子书模式的渲染行为。
