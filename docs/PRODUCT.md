# 产品文档：eink-truescale-pdf

> 文档状态：当前产品基线  
> 更新日期：2026-08-07  
> 适用范围：GitHub 直装版与 Mac App Store 版  
> 事实优先级：当前代码与测试结果 > 本文档 > 历史 PRD、TODO 与开发记录

## 1. 产品概述

eink-truescale-pdf 是一套面向长文档阅读的 macOS 本地转换工具。它把 EPUB、HTML、FB2、Markdown 等流式文档重新排版为尺寸明确、分页稳定的 PDF，并允许用户调整字体、字号、边距和行距。

项目的核心能力不是“把文件后缀改成 PDF”，而是控制 PDF 的真实物理尺寸和排版几何，避免内容在打印、阅读器或电子墨水设备上被二次缩放后出现字号偏差、留白失真和字形模糊。

一句话定义：

> 把流式长文档可靠地转换为适合打印和深度阅读的固定版式 PDF。

## 2. 核心价值

1. **尺寸可理解**：App Store 版以 A4、A5、B5 为主要规格，并用“常规打印纸”“A4 对折大小”“比 A4 小一圈”等说明降低认知负担。
2. **排版可控制**：字体、字号、边距、行距、语言和页脚时间可调，适合阅读而非仅追求格式可打开。
3. **结果可验证**：输出页面尺寸、全书尺寸统一性和常见转换故障由回归测试约束；项目已有 QUADERNO A5 的物理测量基准。
4. **处理在本地**：文件转换不需要账号，不上传用户文档，不包含广告、分析 SDK 或遥测。
5. **输出可迁移**：PDF 可打印，也可由用户自行传输至任意支持 PDF 的设备；Quaderno 版还提供专用的一键投递。

## 3. 产品形态

当前采用“双版本、同内核”结构。

| 维度 | Quaderno Converter（GitHub 直装版） | Epub 转 PDF（Mac App Store 版） |
|---|---|---|
| 主要用户 | 已安装官方 QUADERNO PC App 的电子墨水阅读用户 | 需要把流式文档转换为标准尺寸 PDF 的普通 Mac 用户 |
| 输入 | EPUB、HTML/HTM、FB2、Markdown、粘贴文本、网页链接 | EPUB、HTML/HTM、FB2、Markdown |
| 输出 | QUADERNO 适配 PDF；可另存或发送到设备 | A4、A5、B5 PDF；由用户自行保存和传输 |
| Quaderno 依赖 | 只有一键投递需要官方客户端；转换和另存不需要 | 无，不包含厂商投递功能 |
| 页面规格 | 以已测量的 QUADERNO A5 为主，保留设备参数能力 | A4、A5、B5，避免一次展示过多规格 |
| 网络访问 | 仅在用户主动转换网页链接时获取网页及图片 | 不访问互联网 |
| 分发 | GitHub Release，Developer ID 签名和 Apple 公证 | Mac App Store，App Sandbox |
| 当前版本基线 | 1.1.0 | 1.1.0（提交构建仍待解决平台拒绝） |

两个版本共享的长期资产是：文档解析、Pandoc/Typst 排版管道、PDFKit 预览、字体与版面参数、物理尺寸测量方法以及回归测试。厂商投递属于可替换的外围适配，不应侵入通用转换内核。

## 4. 目标用户与场景

### 4.1 主要用户

- 希望把 EPUB 或本地 HTML 转成便于打印、批注和归档的 PDF 用户。
- 在 Mac 上阅读或整理长文档、论文、教材、AI 输出内容的学生与知识工作者。
- 使用电子墨水设备，希望避免 A4 页面被缩小后字号和清晰度下降的用户。
- 使用 QUADERNO，希望减少“转换—保存—导入”操作步骤的用户。

### 4.2 核心场景

| 场景 | 用户任务 | 产品结果 |
|---|---|---|
| 本地电子书转换 | 选择 EPUB/FB2 并调整版式 | 带目录、大纲、章节分页和元数据的 PDF |
| 本地 HTML 转换 | 选择含文字、列表、表格、公式和本地图片的 HTML | 按文档结构重新排版的 PDF |
| 文本快速排版 | 粘贴 Markdown 或普通文字 | 可预览、另存或投递的 PDF |
| 标准纸张输出 | 选择 A4、A5 或 B5 | 尺寸明确、全书页面统一的 PDF |
| 电子墨水适配 | 采用测量后的显示区尺寸 | 减少设备端二次缩放 |
| Quaderno 投递 | 完成预览后发送 | 调用已安装的官方客户端接收 PDF |

## 5. 功能范围

### 5.1 已实现的公共能力

- 支持 EPUB、FB2、HTML/HTM、Markdown 输入。
- 支持本地 HTML 的相对路径图片，不执行 JavaScript。
- 生成固定版式 PDF；支持目录页、PDF 大纲、章节分页和源文档元数据继承。
- 支持字体、字号、边距、行距、语言和页脚时间设置。
- 参数偏好持久化；失效的字体或选项会回退到有效默认值。
- PDFKit 多页预览、页码跳转和页面尺寸一致性提示。
- “预览”和“另存”会检查输入与参数指纹，避免输出上一份文档或旧版式。
- 应用内置 Pandoc、Typst 与 GNU MP，最终用户无需安装 Homebrew。
- 支持 Apple Silicon，最低 macOS 14；当前分发包不支持 Intel Mac。

### 5.2 Quaderno 版专属能力

- 粘贴文本和 Markdown 转换。
- 网页链接正文抽取、图片内嵌和 PDF 生成；对重 JavaScript、付费墙及强反爬网页只做尽力支持。
- 检测 `/Applications/QUADERNO PC App.app`，在可用时显示“发送到 Quaderno”。
- 投递前制作独立副本，避免官方客户端删除唯一 PDF 产物。
- QUADERNO A5 显示区物理尺寸已经钢尺实测；A4 参数仍需真机复核。

### 5.3 App Store 版专属能力

- 默认 A4（210 × 297 mm，常规打印纸）。
- A5（148 × 210 mm，A4 对折大小）。
- B5（176 × 250 mm，比 A4 小一圈；长宽约为 A4 的 84%，面积约为 A4 的七成）。
- 不包含 Quaderno、快捷投递或网页抓取，不要求安装任何阅读器客户端。
- App Sandbox 下只访问用户明确选择的输入文件、关联本地资源与输出位置。

## 6. 关键交互原则

1. **输入来源始终可见**：文件转换、粘贴文本、网页链接是一级模式，不随内容滚动消失。
2. **主要动作固定在底部**：预览、发送与另存不应被长设置区推出窗口。
3. **先理解、后选择**：纸张规格先展示 A4/A5/B5，并给出日常类比；更多海外规格只有在国际化需求明确后再考虑。
4. **清空可撤销**：文本与链接清空动作应就近放置，并提供短暂撤销机会，避免误删长内容。
5. **失败必须可见**：渲染、网页抽取、设备离线和页面尺寸异常都应给出用户可理解的原因。
6. **不要求先点预览**：另存和发送应自行确保当前输入与排版参数已经渲染为最新 PDF。

## 7. 技术架构

```text
输入文件 / 粘贴文本 / 网页链接
              │
              ▼
       SwiftUI 输入与参数层
              │
              ▼
  Pandoc：解析文档并生成结构化中间表示
              │
              ▼
  Lua 过滤器 + Typst 模板：分页、目录、排版和物理尺寸
              │
              ▼
        Typst：生成 PDF
              │
       ┌──────┴──────┐
       ▼             ▼
 PDFKit 预览       保存 PDF
                     │
                     └─ Quaderno 版可交给官方客户端
```

主要入口：

- `book.sh`：电子书和文件转换主流程。
- `deliver.sh`：剪贴板快速渲染与 Quaderno 投递。
- `deliver.typ`：统一排版模板与页面几何。
- `book-filter.lua`：章节分页、锚点和结构修复。
- `gui/mac/ContentView.swift`：桌面界面与交互编排。
- `gui/mac/ConversionViewModel.swift`：转换状态、参数、预览和保存逻辑。
- `gui/mac/wechat/`：Quaderno 版网页正文抽取与图片内嵌。
- `gui/build-app.sh`：自包含应用构建、二进制重定位与签名。
- `test.sh`：跨 CLI、GUI、页面尺寸和历史故障的回归测试。

## 8. 非目标与边界

- 不绕过 DRM、付费墙、登录限制或网站访问控制。
- 不承诺复刻复杂 CSS、浏览器动画或 JavaScript 动态网页的像素级外观。
- 不把产品扩展成“任意格式之间互转”的大而全工具；核心仍是流式文档到固定版式 PDF。
- App Store 版不包含 Quaderno 投递和网页抓取。
- 暂不增加大量纸张规格；海外市场与多语言完成后再评估 Letter、Legal 等规格。
- 不自动上传、同步或分发用户生成的内容。

## 9. 隐私、版权与开源合规

- 文件转换默认完全在本地完成；不收集文档、文本、偏好或使用数据。
- Quaderno 版只有在用户主动提交网页链接时访问对应网站，且不应将该能力解释为拥有内容分发授权。
- 用户应只转换其有权访问、保存和使用的内容；软件不提供内容再分发平台。
- 项目自身采用 MIT 许可。
- 发布包内含 Pandoc（GPL-2.0-or-later）、Typst（Apache-2.0）和 GNU MP（LGPL/GPL）。许可全文、二进制改动说明和对应源码获取方式必须随版本持续提供。
- 履行源码与许可文本义务不等于已经排除 Pandoc/GPL 与 App Store 标准条款的兼容性风险；正式商业分发仍需保留法律审查闸门。

## 10. 质量标准

每次发布至少满足：

- 所有输出页尺寸统一并等于用户选择的目标规格。
- 含 `@词`、邮箱、`$变量`、数学公式和内部锚点的输入不导致整本渲染失败。
- 中文路径、空格路径、HTML/HTM 大小写扩展名和本地相对图片可正确处理。
- 另存与投递不会输出上一份文档，也不会删除唯一产物。
- 没有 Homebrew 的最终用户环境仍可转换。
- App Store 版保持沙盒、无网络访问和无 Quaderno 残留。
- Quaderno 版的“预览 / 发送到 Quaderno / 另存 PDF”在支持的最小窗口尺寸内可见。

## 11. 成功指标

现阶段不以复杂增长体系为目标，先观察以下指标：

- 转换成功率及失败原因分布。
- 首次安装后成功生成第一份 PDF 的比例。
- EPUB、HTML、FB2、Markdown 的真实使用占比。
- 用户是否需要除 A4/A5/B5 之外的规格。
- Quaderno 一键投递的成功率与设备离线错误率。
- 是否有第二种设备完成物理尺寸实测并贡献数据。

在没有遥测的前提下，上述数据只能通过自愿反馈、支持邮件和可复现问题报告收集；不得为指标擅自加入追踪。

## 12. 近期产品方向

1. 先把 EPUB/HTML/FB2/Markdown → PDF 的成功率、错误提示和大文件体验做到高度可用。
2. 用稳定版 macOS 构建并重新提交 App Store 版，解决当前构建环境拒绝。
3. 保持 Quaderno 版独立迭代，并把设备投递严格限定为外围适配。
4. 补齐中文界面后再做英文国际化与海外纸张规格，避免当前界面认知过载。
5. 在明确网页访问、版权和平台规则前，不把网页解析加入 App Store 版，也不扩张为内容分发能力。
