0. 设计前提与核心判断
--------------------------------------------------------------------------------

站点承担两种性质，必须结构上分开、战略上互补：

  A. 产品站    —— 阅读岛 app 本身（面向普通读者，中文为主）
  B. 技术社区  —— 电子墨水设备技术积累（面向开发者，英文为主）

三条核心判断：

  1. 「方法」与「数据」必须拆开
     方法（推导法 + 校准法）永不过时、适用所有设备 → 长青文章
     数据（各机型尺寸）持续增长、需要他人贡献   → 数据库表
     现在混在一篇里，拆开后方法可被长期引用，数据可不断长大。

  2. 数据必须机器可读
     只有 HTML 表格 = 一篇博客
     同时提供 JSON  = 一个数据源，别人的软件能调用
     一旦有工具依赖它，站点地位完全不同。

  3. 对访客最有价值的不是文章，是校准页 PDF
     文章是解释，PDF 才是工具。必须一键下载、无需任何依赖。

2.1 /lab（实验室首页）
--------------------------------------------------------------------------------
目的：10 秒内讲清「这里有什么、对我有没有用」
内容块：
  · 一句话定位
    「电子墨水设备的物理参数与排版技术资料库」
  · 三个入口卡片：设备参数库 / 校准页下载 / 技术文章
  · 当前收录设备数（诚实显示，哪怕只有 1 台已验证）
  · 最新更新条目
不要放：公司介绍、愿景、宣传语。开发者只想要数据。


2.2 /lab/devices（设备参数库）
--------------------------------------------------------------------------------
目的：本站最核心的资产，随时间增长
内容：
  · 一张主表，列：
      机型 / 屏幕尺寸 / 分辨率 / ppi / 显示区(mm) / 宽高比 / 状态 / 来源
  · 状态必须区分三档，绝不含糊：
      ✅ 已实测   —— 有人用尺子量过，附照片
      ⚠️ 推导值   —— 仅由规格推算，待验证
      ❓ 待补充   —— 已知机型但无数据
  · 可按厂商 / 尺寸筛选
  · 顶部醒目：「贡献你的设备数据」入口
  · 底部：授权声明（建议 CC0 或 CC BY）+ 引用格式

当前种子数据：
  ✅ QUADERNO A5 (FMVDP51)  156.97 × 209.30 mm  227.18 ppi
  ⚠️ QUADERNO A4 (FMVDP41)  202.69 × 270.26 mm  206.77 ppi


2.3 /lab/devices/{slug}（单机型详情页）
--------------------------------------------------------------------------------
目的：承接长尾搜索（如「quaderno a5 screen size mm」）
每页固定结构：
  · 结论前置：显示区物理尺寸（大字）
  · 完整参数表
  · 推导过程（可展开）
  · 验证状态与实测照片
  · 「用于排版时的推荐设置」—— 页面尺寸、边距、字号建议
  · 该机型的校准页 PDF 直链
  · 数据来源与最后更新日期

--------------------------------------------------------------------------------
目的：让站点从「文章」升级为「基础设施」
格式：

    "fujitsu_quaderno_a5_fmvdp51": {
      "vendor": "Fujitsu",
      "model": "QUADERNO A5",
      "sku": "FMVDP51",
      "diagonal_in": 10.3,
      "resolution_px": [1404, 1872],
      "ppi": 227.18,
      "display_mm": [156.97, 209.30],
      "aspect": 0.75,
      "verified": true,
      "method": "steel ruler, 100mm reference line",
      "verified_date": "2026-07-18",
      "source": "https://..."
    }
  }
要求：
  · 稳定 URL，永不变更路径
  · 允许跨域调用（CORS）
  · 版本化或带 last_updated 字段


2.5 /lab/articles（技术文章）
--------------------------------------------------------------------------------
目的：方法论沉淀，承接痛点搜索
首批文章（按优先级）：

  [1] 电子墨水设备显示区物理尺寸测定法
      —— 已完成（docs/quaderno-display-metrics.md 拆分而来，只留方法）
      核心：推导三步法 + 双重自验证 + 校准页判读

  [2] 为什么你的 PDF 在墨水屏上显得模糊
      —— 最高价值的痛点文章
      切入：读者不知道根因是缩放重采样
      核心：重采样导致 hinting 失效 > ppi 高低
      结论：220ppi 精确 1:1 优于 300ppi 带缩放
      这篇最可能被搜到、被转发。

  [3] 电子墨水屏排版实践：页面尺寸、边距、字号
      —— 工程指南，落到可操作参数

文章页要求：
  · 结论前置（TL;DR 表格放最顶）
  · 每篇都指向可下载的产物（校准页 / 数据 / 代码）
  · 标注日期与修订记录


2.6 /lab/calibration（校准页专页）★
--------------------------------------------------------------------------------
目的：本站最实用的单页，很多人只需要这个
内容：
  · 一句话说明用途
  · 【下载 PDF】按钮 —— 放在最顶，不需要读完文章
  · 按机型分列的下载链接（A5 / A4 / 通用可编辑版）
  · 三步使用说明（投到设备 → 尺子量 → 对照判读表）
  · 判读表：
      正好 100mm      → 精确 1:1
      实测 L mm       → 页面尺寸乘以 100/L
      四角标记缺失     → 设备裁边，需另行补偿
      横竖比例不一致   → 宽高比推导有误
  · typst 源码链接（换机型只改两个常量）
  · 「量完了？把数据贡献回来」→ /lab/contribute


2.7 /lab/contribute（贡献指南）
--------------------------------------------------------------------------------
目的：把贡献摩擦降到最低
原则：只要三个数 + 一张照片
内容：
  · 需要提交什么（机型全名 / 实测毫米值 / 校准页照片）
  · 两条提交路径：
      - GitHub PR（面向开发者）
      - 表单 / 邮箱（面向普通用户）
  · 明确署名方式
  · 明确授权（贡献即同意以 CC0/CC BY 发布）

3.1 /tools/print-to-quaderno（主页）
--------------------------------------------------------------------------------
结构（顺序即重要性）：

  ① 一句话价值
     「复制 → 按热键 → 墨水屏出现。零 GUI，全程后台。」

  ② 一张动图或三步图示
     复制 Markdown → ⌃⌥⌘P → 设备显示

  ③ ★ 前置资格闸门（放前面，诚实劝退）
     需要：macOS · 一台 QUADERNO · 官方客户端
     让不符合条件的人 10 秒内离开，而不是装到一半才发现。
     这不是赶人，是尊重时间，也大幅降低支持负担。

  ④ 一行安装
     curl -fsSL <domain>/install.sh | sh

  ⑤ 它解决什么问题（对比：原来要走 6 步 GUI）

  ⑥ 技术栈与设计取舍（链接到 /lab 文章，形成板块互引）


3.2 /tools/print-to-quaderno/start（快速上手）★
--------------------------------------------------------------------------------
术语说明：此处用「快速上手 / Getting Started」而非「onboarding」。
  onboarding 通常指产品内的首次使用引导，默认存在 GUI 承载。
  本工具无界面，引导全部发生在文档与安装脚本中。

五步流程（按今天实战踩坑经验设计）：

  步骤 1  确认前置条件
          清单式勾选，不满足直接止步

  步骤 2  一行安装
          脚本自动：检查/安装 pandoc + typst → 拉取仓库 → 跑自检

  步骤 3  ★ 自检 deliver.sh --check
          这是本产品最关键的一环。
          理由：全链路有 5 个独立环节可能断，且断了全部静默无提示。
          输出示例：
              ✅ pandoc 3.10
              ✅ typst 0.15.1
              ✅ QUADERNO 客户端已安装
              ❌ 设备未连接 —— 请打开客户端确认显示「已连接」
              ✅ 模板 deliver.typ
          把开发期踩过的坑（locale / PATH / 设备离线）固化成代码，
          让后来者不必重走。

  步骤 4  绑定全局热键（唯一必须手动的一步）
          Apple 不允许程序化创建快捷指令并绑定热键（已实测确认，
          快捷指令 App 只能授予只读点击权限）。
          因此这一步永远手动 → 配图必须最详细，逐屏截图。

  步骤 5  ★ 第一次成功 = 啊哈时刻
          安装脚本末尾自动投递一份「欢迎」文档到设备。
          用户抬头看见墨水屏出现内容，同时完成：
            验证全链路 / 教会用法 / 交付情绪价值

  步骤 5.5  顺带做校准（可选但推荐）
          引导用户投一次校准页、量一次尺子。
          → onboarding 顺便变成数据采集，回流喂养 /lab/devices


3.3 /tools/print-to-quaderno/troubleshoot（排错手册）
--------------------------------------------------------------------------------
以退出码为索引（用户能直接报数字）：

  退出码 1   剪贴板为空
  退出码 2   渲染失败（日志在 /tmp/quaderno_render_<PID>.log）
  退出码 4   设备离线或投递被取消
  退出码 10  缺依赖

另附已知坑清单（全部来自实战）：
  · 中文乱码        → locale 缺失，pandoc 回退 latin1
  · 找不到 pandoc   → 快捷指令 PATH 不含 Homebrew
  · 含 @ 的文本崩溃 → pandoc citations 扩展误判为文献引用
  · 字小/发虚       → 页面尺寸错配导致缩放（链到 /lab 文章 [2]）

4. 双语策略
--------------------------------------------------------------------------------

产品板块（/ /download /docs）    中文为主
技术板块（/lab /tools）          英文为主，中文并存

理由：会搜索这类问题的开发者绝大多数使用英文。英文是能否触达世界的分水岭。

路径方案：
  /lab/...          英文（canonical）
  /zh/lab/...       中文
  用 hreflang 互相声明，避免被判重复内容。

标题必须长成别人搜索的样子（真实高价值查询）：
  · quaderno screen size mm
  · 1404x1872 physical dimensions
  · e-ink PDF 1:1 no scaling
  · why does my PDF look blurry on e-ink   ← 痛点搜索，价值最高
    搜的人根本不知道根因是缩放，你能给出他想不到的答案。

5. 闭环设计（本架构的关键）
--------------------------------------------------------------------------------

      用户为了用工具而来
              ↓
      /tools/.../start 引导安装
              ↓
      顺带引导做一次校准（步骤 5.5）
              ↓
      用户量出自己设备的数据
              ↓
      /lab/contribute 回流
              ↓
      /lab/devices 数据库长大
              ↓
      更多搜索流量进入 /lab
              ↓
      更多人发现工具
              ↓
            （循环）

工具带来用户，用户贡献数据，数据带来流量，流量带来用户。
工具与社区互为燃料，而非两个割裂板块。
